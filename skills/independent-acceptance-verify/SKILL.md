# 独立复验签收（不照单签收）

任何岗在签收／终签／放行前使用。**禁止凭报告方的结论或态度签收**，必须独立取证后分级裁定。

**数据真实性铁律**：每个技术要素要有可复算证据；编造按 -50 分/条。

## 触发场景
- 成员交脚本／工具／skill、数据样本、测试报告、核证件、评分复核表、软著材料并请求签收。
- 终签、封缄、封皮、放行前的最后一道核验。
- 下属结论与自己此前判断冲突时（既不因是下属就否，也不因推翻自己就护）。
- **"三关全过"但终检不合格时**——用本 skill 定位"三关到底漏检了哪一层"。

---

## 第 0 步：先问对主体与口径（2026-10-21 新增，**最高杠杆**）

**被验物是什么、由谁提交、依据哪一版、哪一条**——不确认这四项就动手，验的可能是错的题。

- **主体分支**：个人主体 vs 法人（公司）主体，**法定件清单完全不同**。例：软著登记，自然人主体才需要"非职务开发声明"，**公司主体不需要**；法人主体的证明文件是**营业执照**，不是身份证。
- **官方优先于内部规范**：判断"官方／法定／合规"**必须回官方原文**（《办法》《条例》原文），**不得以任何内部规范（章程、台账、裁定、口头）充当官方依据**。内部规范自称"官方必备"**不改变其法律位阶**。
- **"回母本"不等于"回到位"**：母本是内部二手规范，官方才是硬线。**回母本实算只能保证"引的是最新版"，不能保证"引的是对的那一条"**。
- **口径多方打架时先锁一处**：出现"几件／几类／几个"这类计数，若章程、裁定、执行各方说法不一，**当场查清唯一出处**并上报，**任何裁定不得改写章程口径**。
- **条文自相矛盾时，责任在起草不在执行**；但执行方"该回官方未回"这一条仍要认，**两边都要记，不得互相顶替**。

---

## 第 1 步：定位正本，先核指纹

- 用 grep/find 按声称的 md5 反查**正本路径**，`md5 -q` 复算全值与声称值比对；核侧车。
- **侧车规范（团队现行）**：侧车文件名＝`<正本全名>.md5`，内容＝**单行纯 32 位 md5 ＋ 换行，共 33 B**。
  - **不要用含名型（`<md5>  <文件名>`，约 48–67 B）**——那是历史格式，团队标准已归 33B 纯单行。
  - 解析侧车**格式无关**：整行提取首个 32 位 hex（`grep -oE '[0-9a-fA-F]{32}'`），可同时兼容 33B 纯值型、48B GNU 含名型、53B BSD `MD5 (名) = 哈希` 型。
- 多址投递要**逐箱复算计数**，不信"已投 N 箱"的表述。
- **投箱面 ≠ 本区凭据面**：投箱成功不等于本区侧车已落；正文落盘、侧车同值回算、投箱三动作都完成才算交。
- **件在「箱名/日期/件名」三层结构下**——查件必须**递归**（`rglob`），只看「箱名/件名」一层会**凭空报漏投**。
- 先看实物再读结论；md5 不符＝直接打回。

### 1.1 值 + 尺寸双验（**只验尺寸等于没验**）

侧车合规 = **两条同时成立**：
1. **值同值**：侧车里那 32 位 == 实物 `md5 -q` 实算值；
2. **尺寸达标**：侧车字节数 == 33。

**只查字节数会漏断链**（尺寸对、值是旧的）；**只查值会漏格式**（值对、48B 含名型）。

### 1.2 先改实物，后写侧车（**顺序不能反**）

- 正确序：**先改实物 → 再算侧车 → 再验双项**。
- 反序（先写侧车、后改实物）⇒ **侧车立即断链**。且"改完再验"若只验尺寸，**三处错会互相掩盖成一句"看起来全绿"**。
- 归正时**先留痕再改**：断链的旧侧车另存为 `*.md5.stale_<日期>_值断链留痕`，不删。

### 1.3 同名件必比内容版本

**值同值 ≠ 描述现行版**。值同值只证明侧车没撒谎，**不证明它描述的是当前在用的那版**。
- 同名多版本并存时，取用前**比内容指纹**，并明确"正本同名件"与"版本留痕件"（如 `*_v0.1_留痕`）。
- **留痕件不可执行**；`.md5bak` 只能靠 MD5 比对验证，**不运行**。

## 第 2 步：自造最小正反例独立复跑（**不用对方夹具**）

- **不得只跑对方提供的测试／夹具**（可能背答案）。自建最小数据集：1 个全齐正例 ＋ 覆盖其声称能力的反例（缺件／漏投／篡改／侧车缺·空壳·异值／别名归并／多层目录漏扫）。
- **读代码不算验收，必须实跑。** 但要先读代码定位关键分支（如 exit code 行）。
- 数据／情报／核证类：**回官方源逐条对**（专利库、官方 LICENSE/model card、官网报价单、**法规原文**），留取数日；二级稿不算证据。
- 脚本实跑易错点：
  - 管道后 `$?` 是**末条命令**的退出码；须先 `ec=$?` 存值再判断。
  - 侧车名是 `A.md.md5` 不是 `A.md5`，命名错会造成"侧车全缺"的假失败（**先查自己夹具，再怪被测件**）。
  - 先 `python3 -m py_compile` / `bash -n` 验语法，再跑功能。
  - 传 `--help` 之类参数前先确认脚本真的实现了该分支，**否则会把参数当路径跑出无意义 FAIL**，甚至在 `basename -- -` 处直接崩。

---

## 第 3 步：两源（多源）对账

- 同一事实找**两个独立来源**比对（脚本输出 md5 vs 官方 CALL_LOG；官网 vs 报价单；件内数字 vs 我本人在卷记录）。
- 两源独立一致＝口径未被篡改；**冲突必须定位到哪一源错，禁止和稀泥**。
- **交叉印证的目的是排除"尺子自身失明"**：尺子失明时往往**返回空**而非错值——空结果最像"东西不存在"，于是被当成事实连报多日。
- 尺子报错先**分诊**三种性质：①尺子真坏（修尺子）②**我调错了**（改调用，**别去改一件根本没坏的工具**）③**尺子找错了对象**（换对象，不是修尺子）。
- 尺子对某类对象失明时，**先确认自己读的是哪一份注册表／哪一份基线**——本机就曾同时存在两份 `mcp.json`，读错文件导致"自研 MCP＝0"连报多日。

---

## 第 4 步：分级裁定（出书面裁定件）

- **签收**：正反例全中、md5 全等、两源一致、**构成对法定清单、包内痕迹洁净**。
- **有条件签收**：主体为实但有 N 项缺陷——列明等级（🔴/🟠/🟡/🟢）、改法、死点、改后由谁回归；**缺一项硬条件不得签收**。
- **打回**：md5 不符、无实测、造数、关键断言复现失败。
- 裁定须写**"我实测了什么"**（命令／场景／exit／数字），不写"据 XX 称"。
- 功过分记：违规与立功分别留痕、互不抵消。
- **不代笔他人物件**（他人署名代码由作者自改，复验方只给改法）；**不代签他岗责任**。
- 措辞分级：**"值全等"≠"核验完成"**；**"装上"≠"在本会话可直调"**；**"查不到"≠"不存在"**（缺年份／kind code 的查询号 0 结果，不构成不存在结论）。

---

## 第 5 步：留痕投递

- 裁定件命名：`裁定/签收裁定_<事项>_<结论>_<岗>_YYYYMMDD.md`，正文带被验件 md5、我的实测证据表、分级结论、后续死点。
- 生成侧车用单条命令（防空壳）：
  `md5 -q "$F" > "$F.md5"`
- 按岗投箱后**逐箱复算**计数；思维链 R1–R8 存档。
- **已投件要改正时，一律新名更正件，禁原地覆盖**——改原件 md5 会让全部已投侧车断链，制造比原错更大的事故。原件**一字不动**，以**指向性更正件**承载，并复验原件各箱侧车仍全等。
- **报位不等于指责**：发现他岗缺陷，报位＋给改法，不擅改他人文件。

---

## 反模式（禁止）
只读对方报告／只跑对方夹具就签收；因态度好、提前交而放宽；为护自己此前判断而否掉下属实测真证据；把工程量写成金额、把合成/mock 数据写成真实记录；把"方案·待实测"写成"已验证 X%"；用管道退出码冒充被测脚本退出码；**把章程等内部规范当官方依据**；**只验侧车尺寸不验值**；**先写侧车后改实物**；**同名件不比对内容版本就取用**；**清点自研资产时按目录名目视归类而不看 author 字段**。
