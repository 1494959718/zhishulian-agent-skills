# SkillsMP 桥接（MCP）· 自研 MCP 第 4 号 v0.1

> Self-developed MCP bridge for the SkillsMP MCP service — v0.1.
> 本文件是对外说明，**只登记已实跑的事实**，未实跑的一律不写。

## 它解决什么

SkillsMP 官方 MCP 是 HTTP 型服务。本团队实测发现三个问题，导致它**接不进 MCP 客户端**：

| # | 实测问题 | 实测证据 | 桥接件的做法 |
|---|---|---|---|
| ① | 上游只放行 `MCP-Protocol-Version: 2025-06-18`；发旧版本头一律返回 **HTTP 403**（HTML 页面，不是 JSON-RPC 错误） | 复现 3/3 | 转发时强制改写协议版本头 |
| ② | 直连时 API Key 只能写进客户端的 `mcp.json` 配置 ⇒ **明文进配置**（该文件最容易被备份、同步、转发） | 客户端注册 schema 如此 | 改用 stdio 传输，Key 由桥接件**运行时**从本机 0600 权限文件读取，配置文件零明文 |
| ③ | 上游 HTTP 传输连上后数分钟即被断开，客户端不自动重连 ⇒ 工具从目录中消失 | 客户端连接日志：03:35→03:51、03:55→03:59、09:03→09:19 | stdio 传输由客户端每会话拉起新进程 ⇒ 每次会话都是新连接，天然自愈 |

## 实跑证据（口径已锁定，不外扩）

- **stdio 层已实跑**：`tools/list` 返回 **5 个工具**（上游转发 3 个：检索/详情/分类；本地 2 个：通道体检/本件自检）。
- **stdio 层已实跑**：`health` 返回 `reachable=true`、`http=200`。
- **stdio 层已实跑**：本地自检 13 条全过（假上游 6 条 ＋ 真上游活体核对 2 条 ＋ 本地分发 5 条）。

> **本文件不声称「客户端已可直调」。** 客户端侧的工具注入发生在会话启动时，
> 因此「客户端可直调」这一档的判定必须由**客户端侧复验**给出，不在本文件口径内。

## 设计要点

- **只读转发**：不写上游任何数据。
- **版本头自控**：本地对客户端声明 `2024-11-05`（stdio 侧不受上游限制），转发上游时改写为 `2025-06-18`。
- **凭据不落配置**：Key 只存在于本机 0600 权限文件；桥接件每次调用时读取，输出全部掩码。
- **额度纪律**：上游口径下 `tools/list` / `get_skill` / `list_categories` / `initialize` **不消耗检索额度**，
  优先用它们取元数据，检索类调用才消耗额度。
- **收录 ≠ 认证 ≠ 实时存在**：经外部目录检索到的条目，复用前必须回源原始仓库核对路径与内容。

## 边界

- 本桥接件只做协议转发与体检，不替代「复用前回源核对」这一步。
- 上游 API 行为以官方 `https://skillsmp.com/api/llms.txt` 与 `https://skillsmp.com/developers` 为准；
  本文件记录的协议版本要求为 2026-10 实测值，上游变更后须重新实测。
